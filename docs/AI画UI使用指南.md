# AI 画 UI 使用指南

本文介绍 LVGL Designer 中 AI 新建屏幕、修改界面、切换设备预设和排查生成错误的完整流程。AI 不直接执行任意代码，而是生成受约束的结构化操作，经控件注册表和 Schema 校验后写入工程。

设备显示规格、外壳预览和圆屏裁切的详细说明参见 [设备外壳使用指南](设备外壳使用指南.md)。

## 1. 快速开始

### 1.1 打开 AI 面板

AI 面板默认位于右下角。面板收起后，点击右下角 `AI` 按钮重新打开。

面板顶部包含：

- 模型选择；
- AI 设置；
- 清空对话；
- 收起面板。

输入框中按 `Enter` 发送，按 `Shift + Enter` 换行。请求进行时可点击“停止”。

### 1.2 选择模型

| 模型 | 界面名称 | 适用场景 |
| --- | --- | --- |
| `deepseek-chat` | V3 · 快 | 常规新建、增删控件、颜色和布局调整 |
| `deepseek-reasoner` | R1 · 深思 | 复杂布局、约束较多的界面和多步修改 |

通常先使用 V3。需求复杂或多次修改仍不稳定时再切换 R1。

### 1.3 配置 API Key

点击齿轮打开 AI 设置：

1. 输入 DeepSeek API Key。
2. 点击“保存”。
3. 点击“测试连接”。
4. 出现“连接正常”后关闭设置。

个人 Key 只保存在当前浏览器的 `localStorage` 中，不写入工程文件，也不提交到代码仓库。浏览器请求统一发送到同源后端代理，由代理转发到 DeepSeek。

未填写个人 Key 时，系统会尝试使用服务器预置 Key。“清除”会删除本机浏览器保存的个人 Key。

### 1.4 设置温度

温度范围为 0–2：

- `0.2–0.5`：适合精确修改、指定颜色和尺寸；
- `0.6–0.9`：适合大多数 UI 生成；
- `1.0` 以上：创意更多，但偏离约束的概率更高。

生产界面建议使用 1.0 以下。

## 2. AI 能力

AI 当前支持五类结构化编辑能力：

| 能力 | 行为 |
| --- | --- |
| 新建屏幕 | 创建独立 Screen，并自动切换过去 |
| 整屏重画 | 替换当前屏幕的根节点和全部内容 |
| 添加控件 | 向屏幕根或指定容器加入控件 |
| 修改控件 | 修改属性、样式、flag 和 state |
| 删除控件 | 删除指定控件，但不能删除屏幕根节点 |

AI 可以在新建屏幕时指定内置设备预设。例如，新建 WF2D-8620 圆屏界面时，会同时把项目 Display Profile 切换为 240×240 圆形。

## 3. 操作安全机制

AI 输出不会直接作为 XML、C 代码或任意脚本执行。模型先生成结构化操作，设计器再执行以下检查：

- 控件类型必须存在于当前注册表；
- 属性、枚举、样式键和值类型必须合法；
- 屏幕根节点必须是 `obj`；
- 修改和删除的目标必须存在；
- 导出的 `codeName` 必须符合 C 标识符规则；
- 所有屏幕中的控件 `codeName` 必须全项目唯一；
- 重名时自动添加 `_2`、`_3` 等后缀；
- 指定的设备预设必须存在；
- 圆屏请求不能仅通过根节点大圆角模拟；
- 校验失败时最多自动要求模型修复两轮。

只有校验通过的操作才会写入工程。

## 4. 新建屏幕

### 4.1 在当前设备规格下新建

示例：

> 新建一个设置屏幕，包含标题、Wi-Fi 开关、通知开关和保存按钮。

预期结果：

1. 屏幕列表新增独立屏幕；
2. 新屏幕获得合法英文名，例如 `settings`；
3. 设计器自动切换到新屏幕；
4. 原有 `main` 屏幕不被覆盖；
5. 新屏幕继承当前项目显示规格。

若没有出现新的屏幕条目，应先刷新浏览器，再清空旧 AI 对话并重试。

### 4.2 新建真实圆形屏 UI

推荐明确写出型号：

> 新建一个 WF2D-8620 圆形屏设置界面，包含标题、两个开关和保存按钮，所有重要内容放在圆形安全区内。

AI 会在 `create_screen` 操作中指定 `WF2D-8620`：

- 项目显示规格切换为 240×240 圆形；
- 顶部设备下拉框切换为 WF2D-8620；
- 画布使用真实圆形裁切和匹配外壳；
- 新屏幕按 240×240 坐标范围生成；
- 原屏幕不会被新内容覆盖；
- 不会通过给矩形根节点设置大圆角来冒充圆屏。

如果只说“新建一个圆屏界面”，当前会选择唯一的内置圆形预设 WF2D-8620。写出型号可以减少歧义。

显示规格属于项目级配置，因此切换圆形预设会影响项目中的所有屏幕。需要同时维护矩形和圆形产品时，应分别建立工程。详细规则参见 [设备外壳使用指南](设备外壳使用指南.md)。

### 4.3 新建指定矩形设备 UI

示例：

> 新建一个 WF2D-1050 设备的主控屏，左侧显示环境数据，右侧显示三个控制按钮。

AI 应选择 1024×600 矩形预设并创建新屏幕。提示词中同时写型号、用途、主要区域和控件数量，比只写“画一个首页”稳定。

### 4.4 屏幕和控件命名

名称应使用小写英文、数字和下划线，且不能以数字开头。例如：

- `settings`；
- `round_dashboard`；
- `wifi_switch`；
- `save_button`。

Schema v2 会把控件名称导出为 C 符号，因此所有屏幕中的控件 `codeName` 必须全项目唯一。若名称已经存在，AI 执行器会自动避让，例如把第二个 `save_button` 改为 `save_button_2`。

## 5. 修改现有界面

### 5.1 修改当前屏幕

示例：

> 把当前屏幕背景改成深蓝色，标题移到顶部中央，保存按钮放到底部中央。

若没有明确要求“新建屏幕”，AI 会修改或重画当前活动屏幕。

### 5.2 修改选中控件

先在画布或对象树中选中控件。AI 输入框上方会显示：

> 上下文：已选中 控件名（控件类型）

然后输入：

> 把选中的按钮改成红色圆角按钮，宽 120，高 44。

“这个”“它”“选中的按钮”等指代会映射到当前选中控件。未命名控件不能被稳定引用；必要时先在检查器中设置控件名称。

### 5.3 添加控件

示例：

> 在当前屏幕底部增加一个宽 100、高 36 的确认按钮，水平居中，距离底部 18。

如果要加到特定容器，先选中容器或明确写出容器名称。

### 5.4 删除控件

示例：

> 删除 `old_label` 和 `cancel_button`，保留其他控件不变。

AI 不能删除屏幕根节点。需要完全重画当前屏幕时，应明确要求“重画当前屏幕”。

## 6. 分步骤生成复杂界面

复杂界面建议拆成多轮：

1. 先生成整体结构；
2. 再调整颜色和字体；
3. 再调整单个控件尺寸和位置；
4. 最后检查圆屏安全区和交互状态。

示例：

> 新建一个 WF2D-8620 圆屏仪表盘，中央显示百分比，上方显示标题。

> 在当前屏幕底部增加一个宽 100、高 36 的确认按钮。

> 把选中的按钮背景改成蓝色，按下状态改成深蓝色。

这种方式比在一条提示词中描述几十个细节更容易验证、修正和撤销。

## 7. 推荐提示词写法

高质量提示词最好包含：

1. 操作意图：新建、重画还是修改；
2. 设备型号：例如 WF2D-8620；
3. 页面用途：设置页、仪表盘、媒体控制页；
4. 核心控件：标题、数值、开关、按钮、进度弧；
5. 布局关系：顶部、中央、左右分栏、底部；
6. 视觉风格：背景色、强调色、圆角、留白；
7. 特殊约束：圆屏安全区、控件尺寸、文字长度。

### 7.1 圆屏仪表盘

> 新建一个 WF2D-8620 圆形屏仪表盘。深色背景，标题放在顶部安全区，中央显示 65% 和环形进度，底部放一个 96×34 的蓝色按钮。所有内容保持在内切圆内，不要使用矩形大面板模拟圆屏。

### 7.2 矩形设备首页

> 新建一个 WF2D-1040 首页。左侧三分之一显示温度、湿度和空气质量，右侧显示空调、照明和窗帘三个大按钮；背景浅灰，卡片白色，强调色为蓝色。

### 7.3 精确修改

> 把选中的 `save_button` 宽度改为 120，高度改为 40，水平居中，距离底部 20；默认背景为 #2F80ED，按下状态为 #1F5FAF。

### 7.4 避免含糊指令

不推荐：

> 做好看一点。

推荐：

> 保持现有结构，把背景改为 #0B1020，主文字改为白色，次要文字改为 #94A3B8，按钮统一使用 12 px 圆角和 #3B82F6 背景。

### 7.5 图标和文字的使用边界

图标不是文字的全面替代品。建议按以下规则设计：

- 主页、返回、下一页、播放、暂停等高辨识度导航或动作，可以只使用图标；
- 页面标题、设备状态、模式名称、数值单位必须保留文字；
- 保存、结束会话、重启、删除等重要或有风险的操作，使用“图标 + 短文字”；
- 含义可能不明确的图标必须配文字，不要让用户依靠猜测完成操作；
- 小尺寸圆屏可以缩短文字，但不应把整套界面的文字全部替换为图标。

建议的最低字号是：240×240 圆屏不低于 12 px，480×480 方屏不低于 14 px，600 px 以上的横屏不低于 16 px。页面标题、核心数值和主要按钮应高于最低字号；如果内容放不下，应减少信息或分屏，而不是继续缩小文字和图标。

推荐提示词：

> 导航箭头和主页按钮使用图标；页面标题、空气质量状态、模式名称保留文字；开始和结束操作使用图标加短文字，不要把全部文字都换成图标。

## 8. 撤销、重做和保存

普通的一轮 AI 控件操作会形成一条撤销历史：

- `Ctrl + Z`：撤销；
- `Ctrl + Y` 或 `Ctrl + Shift + Z`：重做。

当 AI 同时切换设备预设并创建屏幕时，显示规格和屏幕树目前分别进入历史记录；如需完整恢复到操作前状态，可能需要连续撤销两次。

AI 对话记录不进入工程文件。模型、温度和个人 Key 保存在当前浏览器；UI 工程按本地或云端工程机制保存。

## 9. 当前限制

### 9.1 项目只能使用一个显示规格

同一工程不能让 `main` 使用 1080×720 矩形屏，同时让 `settings` 使用 240×240 圆屏。所有 Screen 共享一个 Display Profile。

### 9.2 只能使用已登记控件

AI 不能生成任意 C、XML 或未知控件。它只能使用当前注册表登记的类型、属性和样式。

### 9.3 复杂业务配置仍需人工完成

当前结构化操作主要覆盖节点、属性、样式、flag 和 state。复杂业务事件、Subject 绑定、外部素材导入和固件动作建议在检查器及对应管理界面中配置。

### 9.4 中文字体需要字形资源

内置 Montserrat 只包含英文和数字。中文显示为方框时，需要导入包含目标字符的中文字体并在样式中使用。参见 [素材管线说明](asset-pipeline.md)。

## 10. 常见问题

### 10.1 AI 说“新建”，但当前屏幕被覆盖

新版使用正式的 `create_screen` 操作。若仍出现旧行为：

1. 强制刷新页面；
2. 点击垃圾桶清空旧对话；
3. 明确输入“新建一个独立屏幕，不要覆盖当前屏幕”。

### 10.2 要求圆屏，但仍是矩形画布

检查顶部设备型号是否已切换为 WF2D-8620。推荐明确输入：

> 新建一个 WF2D-8620 圆形屏界面。

仅要求“圆形风格”可能被理解为使用圆形组件，而不是切换设备规格。

### 10.3 出现 duplicate-code-name 错误

旧版本曾只在单屏内检查名称。新版已改为全项目去重，并自动生成 `_2`、`_3` 后缀。

处理方法：

1. 刷新到最新版本；
2. 清空旧对话；
3. 重试创建；
4. 对历史工程中的重复名称，在对象树或检查器中手工重命名。

### 10.4 出现 Schema 校验错误

Schema 错误表示模型操作不满足工程约束。设计器会自动尝试修复两轮；仍失败时不会把不合法 UI 写入工程。

可通过以下方法降低错误概率：

- 减少一轮中要求的控件数量；
- 使用明确的控件名称；
- 不要求未登记的控件或属性；
- 将复杂需求拆成多轮；
- 刷新页面后清除旧对话再试。

### 10.5 AI 请求失败或没有结果

依次检查：

1. AI 设置中的“测试连接”；
2. 个人 Key 是否有效；
3. 服务器是否配置预置 Key；
4. 本地服务是否可访问 `/api/lvgl/deepseek/chat`；
5. 是否出现 HTTP 401、429、5xx 或 15 秒连接测试超时。

请求进行中可点击“停止”，然后降低提示词复杂度重新发送。

### 10.6 圆屏内容被裁切

输入：

> 按 WF2D-8620 的 240×240 圆形安全区重新布局，所有文字和按钮距离圆周至少 18 px。

也可以选中具体控件后逐个调整。详细安全区规则参见 [设备外壳使用指南](设备外壳使用指南.md)。

## 11. 推荐工作流程

### 11.1 新建圆屏产品 UI

1. 新建独立工程。
2. 输入包含 WF2D-8620 的新建屏幕提示词。
3. 检查顶部型号是否已切换。
4. 检查屏幕列表是否新增条目。
5. 分轮调整布局、颜色和状态样式。
6. 在显示和隐藏外壳两种状态下检查。
7. 在检查器中补充事件和业务绑定。
8. 进入运行模式验证交互。
9. 保存工程并导出。

### 11.2 为现有产品增加设置页

1. 保持设备预设不变。
2. 输入“新建一个独立设置屏幕”。
3. 确认原屏幕未被覆盖。
4. 让 AI 添加设置项。
5. 在检查器中补充事件、Action 和 Subject 绑定。
6. 配置屏幕跳转。

### 11.3 验收清单

- 设备型号正确；
- 屏幕列表真正增加了新屏幕；
- 原屏幕未被覆盖；
- 对象树不存在异常重名；
- 圆屏内容位于安全区；
- 中文字体包含所需字形；
- 运行模式下交互正常；
- 撤销、重做和保存符合预期；
- 导出前跨引用校验通过。
