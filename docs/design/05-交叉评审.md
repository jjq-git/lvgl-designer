# 架构评审:四份子系统设计对抗性找茬报告

> 评审基线:LVGL 9.4.0 本地源码(`vendor/lvgl/`)。本文所有争议点均已回源码核实,引用处标路径。裁决以"一期 9.4-only、单人、MVP 优先、画布即真值"为准绳。

---

## 一、接口矛盾(按严重度降序)

### X1【致命】widget id / name 映射:四份四个说法,直接互斥

| 设计稿 | 主张 |
|---|---|
| A | `id`(UUID,内部)与 `name`(CName,可选)分离;**匿名节点不发 XML name**;name 在 screen 内唯一 |
| B | 命中测试/热更新全靠 name 反查,要求**生成器给每个节点都显式写 name(= JSON 节点 id)** |
| C | IRNode.name 全工程唯一且 `named:false` 节点"仅热更新内部用"——但其 §2.3 XML 样例又写"n4 未命名,不输出 name",**自相矛盾** |
| D | `id = nanoid` 直接作 XML name;且 D 的 `WidgetNode` 压根**没有用户可见 name 字段**,C 变量名无来源;nanoid 默认字母表含大写与 `-`,不满足 A 的 `/^[a-z][a-z0-9_]*$/` 也不是合法 C 标识符 |

后果:B 的 `lvd_obj_at_point` 返回 name,若按 A 匿名节点无 name,画布上点中一个未命名 label 只能拿到 LVGL 自动名(`lv_label_#`),映射不回 JSON 节点,**选中功能直接残废**;按 D 则 C 导出物变量名是乱码。

**裁决(双轨 name,一处生成)**:
- schema 采 A 的 id/name 分离(A §1.1/§5 全部保留)。
- XML **预览通道** emitter 对每个节点强制输出 `name`:有用户 name 用之,匿名节点用 `_x` + uuid 前 8 hex(小写,合法 CName,`_x` 前缀保证不与用户名撞)。前端持 `previewName → uuid` 双向 Map(由 emitter 随 `XmlEmitResult` 返回)。
- XML **导出通道**(可选产物)与 C 通道按 A:匿名节点不发 name、不进 `ui_t`。
- 唯一性作用域:widget name 按 A 的 per-screen;screen/style/subject/const/asset 名按 C 的"全局 C 符号共用一个去重域"(C §1.4 pass5 正确,采纳)。
- D 的 `WidgetNode` 废弃,统一用 A 的 schema;D 删除"id 兼作 name"的全部表述。

### X2【致命】热重载快路径:D/C 押注 `lv_xml_update_from_data`,B 已用源码证伪

源码事实:`lv_xml_update.c:101` 用 `lv_obj_get_child_by_name(lv_screen_active(), widget_name)` 定位——这是**按 `/` 分段的路径式直查**(`lv_obj_tree.h:276`),裸 name 只能命中活动屏的**直接子节点**。D 的 `updateFromXml('<lv_slider name="obj_ab12" x="30"/>')` 对任何嵌套一层以上的控件必定失败;C 的 `emitXmlUpdateFragment` 同病。B 的评估(§5.1)正确且给出了替代:`lvd_update_attrs` 直调 `proc->apply_cb`,用 `lv_obj_find_by_name`(全树递归,`lv_obj_tree.h:262`)。

**裁决**:采纳 B 的三级热重载协议(§5)整体。删除 C 的 `emitXmlUpdateFragment`、D 的 `updateFromXml`。D 的 `reloadPipeline` 分流骨架保留,但快路径签名改为 `bridge.updateAttrs(previewName, widgetClass, attrs)`——注意 D 的 `LvglBridge` 接口缺 `widgetClass` 参数,该参数由 registry 查 `xmlTag` 提供。attrs 值的字符串格式化复用 A §4.4 的格式化表(放 schema 包,codegen 与 reloadPipeline 共用,不再各写一份)。

### X3【严重】widget 描述表写了三份,结构互不兼容

A 的 `src/registry/*`(WidgetSpec:channel/c-setter/companions/ChildSpec,信息最全)、C 的 `src/codegen/descriptors/*`(WidgetDescriptor + PerVersion)、D 的 `packages/schema/src/widgets/*`(UI 向 PropSpec)。三份表 = 三份漂移源,直接违背"单一事实源"。

**裁决**:**一份表**,位置用 D 的 `packages/schema/src/widgets/`,结构以 A 的 `WidgetSpec/PropSpec` 为基(唯一覆盖了 `channel: 'c-only'`、`companions`、`ChildSpec.kind` 这些真实需求),合并进 C 的 `PerVersion<CSetter>` 字段形态(8.4 接缝)与 D 的 `ui.label/group/control` 字段(A 本来就有,保留)。检查器、XML emitter、C emitter、校验器四方全部消费此表。D §7.1 的"从 parser 源码 grep `lv_streq` 自动对账"CI 检查是四份里唯一的防漂移机制,**必须保留**并对准这份唯一的表。

### X4【严重】仓库/目录结构:三份单 app 布局 vs D 的 monorepo

A(`src/model`+`src/registry`)、B(`src/wasm`+`src/canvas`+顶层 `runtime/`)、C(`src/codegen/**`)、D(pnpm workspace 四包)。文件路径级全面冲突。

**裁决**:采纳 D 的 monorepo(理由成立:codegen 需脱浏览器跑 vitest/golden)。归并表:

| 原设计路径 | 归入 |
|---|---|
| A `src/model/*`、`src/registry/*` | `packages/schema/src/`(schema.ts / migrations / widgets / styleProps / enums / format.ts) |
| C `src/codegen/*`(删 descriptors/) | `packages/codegen/src/` |
| B `src/wasm/*` | `packages/lvgl-runtime/src/` |
| B `runtime/*`(CMake/lv_conf/bridge.c 以 B 为准) | 顶层 `runtime/`,产物出到 `packages/lvgl-runtime/dist/` |
| B `src/canvas/*` + D `apps/designer/src/*` | `apps/designer/src/`(画布交互以 B 为准,面板/store 以 D 为准) |

### X5【严重】WASM 构建形态:B 双文件 MODULARIZE vs D 的 `SINGLE_FILE=1`

D 目录树注释写 `-s SINGLE_FILE=1` 且 dist 只有单 `.mjs`;B 用一整节论证必须 `MODULARIZE+EXPORT_ES6+非 SINGLE_FILE`(流式编译、工厂多实例、Vite code-split)。

**裁决**:B 胜,理由充分。D 的 `runtime/CMakeLists.txt` 注释、`dist/` 布局、git-lfs 说明全部按 B 改(双文件 `.mjs + .wasm`)。

### X6【严重】桥接口存在两份不同签名,且 tick 可注入性互相矛盾

D 自定义了 `LvglBridge`(`createScreen/updateFromXml/snapshotPng/tick(ms)`),与 B 的 `LvglRuntime`(`reloadScreen/updateAttrs/snapshot→ImageData`)方法集、语义、错误处理(B 抛 `LvglError` 带日志行,D 返回 boolean)全不同。更实质的矛盾:**D 的 e2e 依赖 `bridge.tick(ms)` 手动步进保证截图确定性,但 B 的 tick 源是 `lv_tick_set_cb(SDL_GetTicks)`(`lv_sdl_window.c:101`),JS 无法注入时间**——按 B 的设计 D 的测试方案不成立。

**裁决**:以 B 的 `LvglRuntime` 为唯一契约(它背后有 bridge.c 逐函数支撑),D 的 `LvglBridge` 删除,mockBridge 改为实现 B 接口。为满足 D 的确定性测试(合理需求),bridge 补两个导出:
```c
EMSCRIPTEN_KEEPALIVE void lvd_set_manual_tick(int enable);  /* lv_tick_set_cb 切换到手动计数器 */
EMSCRIPTEN_KEEPALIVE void lvd_advance_tick(uint32_t ms);    /* 手动推进 + lv_timer_handler */
```
错误路径统一为 B 的"日志钩子聚合 + 抛 LvglError",D 的 boolean 返回废弃。

### X7【中】资产注册双通道并存

A/D 让字体/图片走 globals XML(`<fonts><tiny_ttf as_file="true">` / `<images><file>`);B 提供 `lvd_register_image` / `lvd_register_font_tiny_ttf` 直接 C 注册。两条并存会有注册时序与重名冲突(源码里 font 注册有查重直接跳过,`lv_xml_component.c:383-389`,**同名换文件不会生效**)。

**裁决**:一期统一走 B 的 bridge 直注册进 globals scope(`lv_xml.c:405,438` 证实 scope=NULL 落 globals),**globals.xml 只承载 consts/styles/subjects**。理由:资产增删/替换频繁,直注册可独立于组件重载做增量;走 XML 则每换一张图都要触发 globals 级重载(见缺口 G1 的大坑)。C 的 `emitXml` globals 输出相应裁剪。附带修正:B 的 lv_conf 表**漏了 `LV_USE_TINY_TTF=1`**(D 有列),必须补上,否则 `lvd_register_font_tiny_ttf` 编不过。

### X8【中】画布 overlay 坐标换算方式不同

B:overlay(SVG)与 canvas 同置于一个 `translate+scale` 容器,内部全用 LVGL 逻辑坐标,换算只在指针事件一处;D:overlay 绝对定位,`rect × zoom` 手工换算,且 D 的换算式 `(clientXY - canvasRect)/zoom` **漏了 pan 项**。

**裁决**:采纳 B §4.1 整体(含手柄 `scale(1/zoom)` 反补偿、`image-rendering: pixelated`);D 的 `Overlay.tsx` 实现按 B 重写,手柄命中并入 B §4.2 状态机(stage 统一 pointer 捕获 + `data-handle`),不用 D 的"手柄 pointer-events:auto"方案(与 B 的 stage 统一监听冲突)。

### X9【中】工程导出格式:A 的 zip vs D 的 base64 单文件

A:下载 = zip(`project.lvproj.json + assets/**`);D:单 `.lvproj.json`,素材 base64 内嵌 `assets[i].data`。

**裁决**:一期采 D(单文件,免 zip 依赖,单人场景体积可控);A 的 `AssetFileRef` 增加可选 `data?: string(base64)` 字段兼容。工程超 ~20MB 再升级 zip,schema 不用动。内部 IndexedDB 内容寻址分离存储两家一致(A §1.6 / D §5.3),保留。

### X10【中】schema 细节层三处对不上

1. **颜色**:A 存 `'#RRGGBB'`,C 的样例 JSON 存 `"0x00a2ff"` 字符串,IR 存 number。裁决:JSON 层以 A 为准(`#RRGGBB`),IR 层 number(C 对),转换在 normalize;C §2.3 样例更正。
2. **键名**:C 样例用 `min`/`max`,违反 A 的"JSON 键 = XML 属性名"铁律(应为 `min_value`/`max_value`);C 的 `styleInline` 结构与 A 的 `InlineStyleGroup` 不同。裁决:全按 A;C 的 normalize 输入类型直接 import `@lvd/schema` 的 `LvProject`,不得自定义输入形态。
3. **SubjectDef**:C 有 `min/max`(源码支持,`lv_xml_component.c:489-501`,**A 漏了,补进 A 的 schema**);C 的 `strBufLen` 默认 64 与 XML 通道**固定 256** 不符(`lv_xml_component.c:509` 写死 buf 256)——C 侧生成必须同为 256 才能双通道等价,`strBufLen` 字段删掉。

### X11【低】codegen 输出选项冲突

A 的 `CodegenOptions.filePrefix('ui_')` 与 C 的具体文件布局(`objects.h/styles.c/actions.c`,无前缀概念)不兼容。裁决:C 的文件布局为准,删 `filePrefix`(YAGNI);A 的 `outputDirName/exportXml/userIncludes` 保留。

## 二、缺口(四份都没覆盖、必须补)

### G1【最重】globals(subjects / 全局样式 / consts)的热重载生命周期

四份都只写了 screen 级重载(B §2.3 五步序列很扎实),**没人回答"subject 定义或全局样式变了怎么办"**。源码事实:
- 重注册 `"globals"` 走特殊分支:`lv_memcpy(global_scope, &state.scope, ...)`(`lv_xml_component.c:171-173`)——直接覆盖 scope 结构体,旧链表(subjects/styles/fonts)**既不释放也不摘除**,泄漏 + 旧 style 指针被遮蔽。
- `lv_xml_component_unregister` 释放 subject 时直接 `lv_free(subject->subject)`(`lv_xml_component.c:305-312` 同款代码),**不调 `lv_subject_deinit`**,不摘 observer——任何仍存活的 screen 实例上的 `bind_value` observer 持悬垂指针,下一次 subject 通知即野指针。

**裁决**:热重载协议补 **L4 = 全工程重载**:销毁全部 screen 实例(含未加载的)→ `lv_xml_component_unregister("globals")` → 重注册 globals → 逐屏重建。bridge 补:
```c
EMSCRIPTEN_KEEPALIVE int lvd_reload_all(const char * globals_xml,
                                        const char ** screen_names,
                                        const char ** screen_xmls, int n);
```
diff 路由规则补一条:**subjects/全局 styles/consts/字体任何变更 → L4**。`unregister("globals")` 后 `get_scope("globals")` 返回 NULL 时各 register 函数的行为(`lv_xml.c:405+`)进 M0 验证;若不可靠,兜底 = runtime 整体 destroy+recreate(成本要在 M0 量出来)。

### G2【重】XML 解析错误行号 → JSON 节点的映射表没有生产者

B §3.2 假设"上层用 XML 生成器输出的行号→JSON 节点映射表定位到具体控件",但 C 的 `XmlEmitResult` 里**没有这个输出**。裁决:C 接口改为:
```ts
screens: { name: string; xml: string; lineMap: { line: number; nodeId: string }[] }[];
```
`xml-writer.ts` 逐节点记行号,一行代码的事,但没接口就永远没人写。

### G3【重】事件回调 stub 注册在 bridge 上没有出口

A §6.3 与 C §2.2 都要求预览时把 IR 收集到的回调名经 `lv_xml_register_event_cb(NULL, name, stub)` 注册(`lv_xml.c:655`),否则含 `<lv_obj-event_cb>` 的屏解析直接失败——但 B 的 bridge 导出清单里**没有对应函数**。裁决:bridge 补:
```c
EMSCRIPTEN_KEEPALIVE int lvd_register_event_stub(const char * cb_name);
/* stub 统一 trampoline:EM_JS 上报 (cb_name, event_code) 给 JS 做高亮/日志 */
```
reloadPipeline 在 register 之前先批量注册本次 XML 引用的全部回调名。

### G4【中】字体/图片替换的失效链路

- 换字体文件或改 tiny_ttf 字号:正在被 label 引用的 `lv_font_t` 若被释放/重建即悬垂,四份都没定顺序。裁决:字体任何变更 → L4(先拆屏,后换字体,再重建)。
- 换图片内容(同名同路径):LVGL image cache 缓存已解码位图,MEMFS 覆写文件**不会自动失效**;且 XML 层 font 同名注册直接跳过(`lv_xml_component.c:383`)。裁决:bridge 补 `lvd_drop_image_cache(const char * src)`(内部 `lv_image_cache_drop`),图片替换 = 写 MEMFS → drop cache → L3/L4。进 M0 验证。

### G5【中】启动/恢复时序:IndexedDB → MEMFS 的重灌协议

刷新页面后 MEMFS 是空的,D 的 assetStore 与 B 的 `writeAsset` 之间没有启动时序约定。裁决:`apps/designer` 定死启动管线:`loadProject(IndexedDB)` → `LvglRuntime.create` → 全量 `writeAsset + lvd_register_*` → `lvd_reload_all`。写进 `reloadPipeline.ts` 的初始化分支,而非散落 useEffect。

### G6【中】多屏切换与屏列表同步

B 有 `lvd_reload_screen`(重建并加载)但没有**不重建的纯切屏**;D 的 ScreenList 面板需要。裁决:bridge 补 `lvd_load_screen(const char * name)`(`lv_display_get_screen_by_name` + `lv_screen_load`);未创建过的屏由 JS 侧先走 register+create。

### G7【低】screen 与 component 的 XML 边界没人明说

A §1.8 定了 ComponentDef schema,C 的 IR 有 IRComponent,但一期 UI 不做组件——那么 **XML emitter 一期只允许输出 `<screen>` 文档、永不输出 `<component>`**,且校验器拒绝 `components` 非空数组进入 emit。一句话约定,写进 C §2.2,防止半实现路径。

### G8【低】预览运行态的 subject 值易失性约定

预览里拖 slider 改了 subject 值,回设计态怎么办?裁决:明文约定"运行态状态易失,退出运行态即触发一次 L3/L4 复位"(B §4.3 已有"可选 reloadScreen 复位",升级为强制),subject 调试面板二期。

### G9【低】色深保真度声明

B 固定 `LV_COLOR_DEPTH=32`,而主力目标是 RGB565 屏,渐变条带/抖动在预览里看不出来,轻微违背"画布即真值"。一期接受,但要在 UI(显示器设置旁)和文档里**显式声明该偏差**;16bpp runtime 变体列二期。

## 三、过度设计(一期砍/推迟)

### O1【砍】C 的 pass4 样式自动去重提升(styleHoistThreshold)

三宗罪:① hoisted 样式名 `s_<hash6>` 随任何属性微调而改名,C 导出物 diff 不稳定、用户业务代码无法引用;② 与 B 的热重载分级冲突——内联样式改动本是 L1 快路径,被自动提升成命名样式后同一个编辑动作变 L3,行为不可预测;③ 与 A §4.3 的"检查器改属性=写 inline,显式命令才提升"心智模型矛盾。**裁决:砍。样式归属完全显式(A 的模型),pass4 二期降级为"检测重复并建议提取"的 lint 工具,绝不默认执行。**

### O2【推迟】C §5.3 XML↔C 双 WASM 像素对拍 CI

要额外维护一个"golden C 编进 WASM"的构建管线 + Playwright 矩阵。一期保留 C §5.1 golden 文本快照 + §5.2 host gcc 编译冒烟(这两个便宜且高价值),像素对拍与 `lv_xml_test` 集成推到 M3+/nightly。

### O3【砍/缩】A 的 schema 尾巴

- `play_timeline` 事件:A 的 EventAction 引用 `timeline: CName`,但 **LvProject 里根本没有 timelines 集合**(A 内部自洽都没过);XML 侧 `<timelines>` 解析虽存在(`lv_xml_component.c:515`),UI/emitter 工作量大。裁决:连 schema 一起删,二期 timelines 成套加。
- `bind_style` 绑定、subject `color` 类型、TranslationPack、consts 编辑面板:schema 字段保留(不值当破坏格式),**UI 与两个 emitter 一期全部不实现**,校验器只接受空。
- A §6.1 的 cPatch"哨兵注释再生成保留"逻辑:cPatch 内容本就存在 JSON 里,不存在丢失问题,重生成直接重排即可,哨兵机制砍成纯注释装饰。

### O4【缩】D 的 mockBridge 影子布局树

mock 要"用默认尺寸粗排 + 2D canvas 画色块"约等于再写半个布局引擎,且与真值必然漂移误导开发。裁决:mock 降级为接口打桩(方法可调、返回固定值/空),不画影子树;真 WASM 是 M0 交付物,前端先行窗口很短。D 的"wasm 加载失败自动回落 mock + 黄条"保留。

### O5【缩】杂项

- C §4.3 的 `LoweringRule` 三型降级框架:留 `Emitter` 接口 + `PerVersion` 字段即可,LoweringRule 类型现在写是纯猜,删。
- D §6.1 snapshots 环形备份 + 崩溃恢复标记:一期简化为 projects 表 + debounce 2s + `beforeunload` flush。
- B 的"设计态无脏区降到 rAF/3 帧"智能节流:推迟,先跑满 rAF。
