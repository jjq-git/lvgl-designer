# 代码生成器子系统设计(IR → Emitters)

> 适用范围:LVGL Web Designer 一期(LVGL 9.4)。本文所有 XML 语法结论均核对自 `vendor/lvgl/src/others/xml/` 与 `vendor/lvgl/tests/src/test_assets/xml/`、`tests/src/test_cases/xml/` 实测代码,引用处标注文件路径。

## 0. 定位与目录结构

代码生成器是纯函数库:输入自有工程 JSON(单一事实源),输出字符串文件集合。不碰 DOM、不碰 WASM,可在 Web Worker / Node(CI)双端运行。

```
src/codegen/
├── ir/
│   ├── types.ts            # IR 类型定义(§1.2)
│   ├── normalize.ts        # ProjectDoc → IRProject 规范化管线(§1.4)
│   ├── style-dedup.ts      # 样式去重/提升 pass
│   └── naming.ts           # C 标识符/XML name 生成与去重
├── descriptors/
│   ├── types.ts            # WidgetDescriptor / PropDescriptor(§1.3)
│   ├── widgets/*.ts        # 每 widget 一个描述文件(obj.ts, slider.ts, ...)
│   └── style-props.ts      # 样式属性描述表(名称、类型、9.4 setter、XML attr)
├── emitters/
│   ├── emitter.ts          # Emitter 抽象接口(§4.1)
│   ├── xml/
│   │   ├── xml-emitter.ts
│   │   └── xml-writer.ts   # 带缩进/转义的 XML 打印器
│   └── c94/
│       ├── c94-emitter.ts
│       ├── c-writer.ts     # C 代码打印器(缩进、注释头、guard)
```

## 1. IR 设计

### 1.1 管线

```
ProjectDoc (自有 JSON, schema 版本化)
  │  pass 1: resolveRefs      — 资源/组件/subject 引用解析,悬空引用 → Diagnostic
  │  pass 2: lowerSugar       — 编辑器糖(如 "圆屏预设")降为普通属性;事件/绑定归一化
  │  pass 3: eliminateDefaults— 按 widget 描述表删除 == 默认值的属性
  │  pass 4: dedupStyles      — 匿名样式集合去重,≥2 处复用提升为命名 style
  │  pass 5: assignNames      — 生成全局唯一 name(XML name 属性 = C 结构体字段名)
  ▼
IRProject  ──→ XmlEmitter ──→ *.xml(预览通道)
           └─→ C94Emitter ──→ src/ui/*(导出物)
```

IR 是**已完全解析、无版本语义、无编辑器概念**的树:emitter 不需要再查引用、再判默认值。取舍:把复杂度全部压进 normalize,两个 emitter 都退化成"树的直译",这是保证 XML↔C 语义等价(§5.3)的结构性前提。

### 1.2 IR 类型定义(`src/codegen/ir/types.ts`)

```ts
export type LvglVersion = '9.4' | '8.4';

/* ---------- 值 ---------- */
export type IRValue =
  | { kind: 'int'; value: number }
  | { kind: 'float'; value: number }
  | { kind: 'bool'; value: boolean }
  | { kind: 'string'; value: string }
  | { kind: 'color'; value: number }                 // 0xRRGGBB
  | { kind: 'size'; value: number | 'content'; unit: 'px' | '%' } // lv_xml_to_size 支持 px/%/content
  | { kind: 'enum'; enum: string; value: string }    // 如 { enum:'slider_mode', value:'range' }
  | { kind: 'flags'; enum: string; values: string[] }// 如 border_side full / ctrl_map 位或
  | { kind: 'constRef'; constId: string }            // 引用 IRConst(XML 用 #name,C 用 #define)
  | { kind: 'assetRef'; assetId: string }            // 字体/图片
  | { kind: 'gradRef'; gradId: string };

/* ---------- 工程 ---------- */
export interface IRProject {
  schemaVersion: 1;
  name: string;                       // C 前缀用,如 "my_ui"
  display: { width: number; height: number; shape: 'rect' | 'round' };
  consts: IRConst[];
  styles: IRStyle[];                  // 已含用户命名 + 提升的匿名样式
  gradients: IRGradient[];
  subjects: IRSubject[];
  assets: { fonts: IRFontAsset[]; images: IRImageAsset[] };
  components: IRComponent[];          // 用户自定义可复用组件
  screens: IRScreen[];
  entryScreenId: string;
}

export interface IRConst {
  id: string; name: string;           // name 已是合法 C 标识符
  type: 'int' | 'px' | 'color' | 'string';  // 对应 <consts> 子标签,见 tests/src/test_assets/xml/globals.xml
  value: IRValue;
}

/* ---------- 样式 ---------- */
export interface IRStyle {
  id: string;
  name: string;                       // s_accent 等;提升产生的为 s_<hash6>
  props: Record<string, IRValue>;     // key = LVGL 样式属性名(bg_color, radius, ...)
  origin: 'user' | 'hoisted';
}
export interface IRStyleRef {
  styleId: string;
  selector: { states: string[]; parts: string[] };  // ['pressed'], ['knob']
}
/** 未提升的就地样式:直接挂在节点上 */
export interface IRInlineStyle {
  selector: { states: string[]; parts: string[] };
  props: Record<string, IRValue>;
}

export interface IRGradient {
  id: string; name: string;
  type: 'linear' | 'radial' | 'conical';
  params: Record<string, string>;     // start/end/center/edge... 原样透传
  stops: { color: IRValue; offset?: IRValue; opa?: IRValue }[];
}

/* ---------- subjects ---------- */
export interface IRSubject {
  id: string; name: string;
  type: 'int' | 'float' | 'string' | 'color';       // lv_observer.h:31-39 的可落地子集
  initial: IRValue;
  min?: number; max?: number;         // 仅 int:<int min_value max_value>(test_xml_subject.c)
  strBufLen?: number;                 // 仅 string:lv_subject_init_string 的 buf 尺寸,默认 64
}

/* ---------- 资源 ---------- */
export interface IRFontAsset {
  id: string; name: string;
  source: { kind: 'builtin'; cName: string }        // lv_montserrat_14 等
        | { kind: 'ttf'; file: string; size: number; range: string };  // 转 lv_font_conv C 数组
}
export interface IRImageAsset {
  id: string; name: string;
  file: string;                       // 工程内相对路径
  colorFormat: 'RGB565A8' | 'ARGB8888' | 'auto';
}

/* ---------- 节点树 ---------- */
export interface IRScreen {
  id: string; name: string;           // screen_main → XML 组件名 & C 函数后缀
  root: IRNode;                       // root.type === 'obj',承载屏幕背景样式
}
export interface IRComponent {
  id: string; name: string;
  extends: string;                    // 'obj' | 'button' | ...
  params: { name: string; type: 'string'|'int'|'color'|'style'; default?: IRValue }[]; // <api><prop>
  root: IRNode;
}

export interface IRNode {
  id: string;                         // 工程 JSON 稳定 id
  name: string;                       // 全屏唯一、合法 C 标识符;== XML name 属性 == objects 字段名
  named: boolean;                     // 用户显式命名(true)才进 objects.h;false 仅热更新内部用
  type: string;                       // 'slider' | 'label' | ... | 'component:<id>'
  props: Record<string, IRValue>;     // 已消除默认值的本地属性(value/min_value/align/flags/states...)
  styleRefs: IRStyleRef[];
  inlineStyles: IRInlineStyle[];
  bindings: IRBinding[];
  events: IREvent[];
  children: IRNode[];

/* ---------- 绑定(归一化后) ---------- */
export type IRBinding =
  | { kind: 'value';   subjectId: string }                              // slider/arc/bar/dropdown/roller/spinbox: bind_value
  | { kind: 'text';    subjectId: string; fmt?: string }                // label/span: bind_text (+bind_text-fmt)
  | { kind: 'checked'; subjectId: string }                              // obj: bind_checked
  | { kind: 'flag';    subjectId: string; flag: string;
      op: 'eq'|'not_eq'|'gt'|'lt'|'ge'|'le'; refValue: number }         // bind_flag_if_*
  | { kind: 'state';   subjectId: string; state: string;
      op: 'eq'|'not_eq'|'gt'|'lt'|'ge'|'le'; refValue: number };        // bind_state_if_*

/* ---------- 事件(归一化后) ---------- */
export interface IREvent {
  trigger: string;                    // 'clicked'|'value_changed'|... (lv_xml_base_types.c:241 的词表)

export type IRAction =
  | { kind: 'callback'; name: string; userData?: string }               // → actions.h 桩
  | { kind: 'subject_set'; subjectId: string; value: IRValue }          // subject_set_{int,float,string}_event
  | { kind: 'subject_toggle'; subjectId: string }
  | { kind: 'subject_increment'; subjectId: string; step: number; min?: number; max?: number }
  | { kind: 'screen_load';   screenId: string; animType?: string; duration?: number; delay?: number }

  severity: 'error' | 'warning';
```

**取舍说明**
- `IRBinding`/`IRAction` 的枚举成员一一对应 lv_xml 已注册元素(`lv_xml.c:216-247` 的 `lv_xml_register_widget("lv_obj-...")` 列表),不发明 LVGL 没有的绑定语义——保证 XML 通道零胶水可预览。
- `name` 同时充当三个身份(XML `name` 属性 → `lv_obj_set_name`,obj parser `lv_xml_obj_parser.c:88-91`;热更新 `lv_xml_update_from_data` 的定位键,`lv_xml_update.h:29`;C `objects` 结构体字段),在 IR 层一次性定死,消除两通道命名漂移。

### 1.3 Widget 描述表(`src/codegen/descriptors/types.ts`)

单一描述表同时驱动:属性面板 schema、默认值消除、XML 属性名映射、C setter 映射、8.4 降级。

```ts
export interface PerVersion<T> { '9.4': T; '8.4'?: T }   // 8.4 二期填充

export interface WidgetDescriptor {
  type: string;                        // 'slider'
  inherits: 'obj' | null;              // 属性继承链(obj 的 flags/states/style_* 全员可用)
  xmlTag: string;                      // 'lv_slider'(9.4 有 parser 的 23 个 + obj;见下)
  create: PerVersion<string | null>;   // 'lv_slider_create';8.4 无此件时 null → 降级钩子
  props: Record<string, PropDescriptor>;
}

export interface PropDescriptor {
  type: IRValue['kind'];
  enum?: string;                       // type='enum' 时的枚举表 id
  default?: IRValue;                   // 用于 pass 3 消除;与 LVGL 构造后初值一致
  xmlAttr: string | null;              // null = 9.4 parser 不支持,XML 通道丢弃并出 warning
  c: PerVersion<CSetter | null>;
}
export type CSetter =
  | { fn: string; extraArgs?: string[] }         // lv_slider_set_value(obj, v, LV_ANIM_OFF)
  | { custom: (v: IRValue, objExpr: string) => string };  // 少数不规则 API 的逃生舱
```

**一期 widget 白名单** = 有 XML parser 的 23 个 + obj(`vendor/lvgl/src/others/xml/parsers/` 目录实测):arc, bar, button, buttonmatrix, calendar, canvas, chart, checkbox, dropdown, image, keyboard, label, obj, qrcode, roller, scale, slider, spangroup, spinbox, switch, table, tabview, textarea。led/spinner/line/imagebutton/msgbox **没有 parser**,编辑器一期不提供这些控件(而不是"C 能导 XML 不能预览"的半残状态)——理由:画布即真值,不可预览的控件违背产品核心承诺。

### 1.4 规范化各 pass 细节

**pass 3 默认值消除**:对每个节点属性,`deepEqual(props[k], descriptor.props[k].default)` 则删除。默认值以"LVGL 构造后的实际初值"为准,录入描述表时逐个对照 widget 源码(如 slider max 默认 100)。效果:XML/C 输出最小化、golden 快照稳定、编辑器"重置为默认"有依据。

**pass 4 样式去重/提升**(`style-dedup.ts`):
1. 把节点上的每个 `IRInlineStyle` 规范序列化:属性名排序 + IRValue 规范打印,SHA-1 取前 6 hex 作指纹;
2. 全工程统计指纹出现次数;≥ `styleHoistThreshold`(默认 2)的提升为 `IRStyle{ name: 's_'+hash, origin:'hoisted' }`,原地替换为 `IRStyleRef`;
3. 用户显式命名的样式无条件保留为 `IRStyle`(即使只用一次);
4. 未达阈值的保留为 `IRInlineStyle` → XML 走 `style_xxx[:state[:part]]` 内联属性,C 走 `lv_obj_set_style_xxx(obj, v, selector)`。

理由:命名样式在 C 侧是共享 `static lv_style_t`(省 RAM、改一处全生效),内联属性在 LVGL 内部走 per-object local style;阈值=2 是"共享收益 > 命名污染"的最小点。选择器必须参与指纹(同属性不同 selector 不可合并)。

**pass 5 命名**(`naming.ts`):`toCIdent(userName) || `${type}_${n}``;全工程去重(后缀 `_2`);保留字表(C 关键字 + `ui/root/screen` 前缀冲突)。screen 名与 subject 名、样式名共用同一个去重域,因为它们都会成为 C 全局符号。

### 2.2 接口

```ts
// src/codegen/emitters/xml/xml-emitter.ts
export interface XmlEmitResult {
  globals: string;                          // globals.xml(consts+styles+subjects+assets)
  components: { name: string; xml: string }[];
  screens:    { name: string; xml: string }[];
  diagnostics: Diagnostic[];
}
export function emitXml(ir: IRProject): XmlEmitResult;

/** 供画布热更新用:单节点属性 diff → lv_xml_update_from_data 片段 */
export function emitXmlUpdateFragment(node: IRNode, changed: Record<string, IRValue>): string;
```

实现要点:
- 每个 screen 输出为独立组件注册(名字=screen name),`<screen><view>…</view></screen>` 结构;样式/常量按"该 screen 用到的"就近内嵌到各 screen 文档的 `<styles>/<consts>`(scope 内查找优先,`lv_xml_style.c:374-383` 落到 globals 兜底),subjects 只进 globals(跨屏共享)。
- 事件 `callback` 动作直接输出 `<lv_obj-event_cb>`;画布运行时用 `lv_xml_register_event_cb(NULL, name, designer_trampoline)` 把 IR 中收集到的全部回调名注册到一个记录/高亮用的空转函数上,预览不炸。
- `emitXmlUpdateFragment` 是画布"属性面板改一个值不重建整屏"的快路径;结构性变更(增删节点/改样式)才走 unregister+register+create 全量路径。

### 3.1.1 多目标导出(emitC94 第二参 options.target)

`ui_conf.h`(include 路径开关,照顾 ESP-IDF `lvgl.h` 与裸工程 `lvgl/lvgl.h` 两种布局):

```c
#include "lvgl.h"
#else

/* 回调 weak 兜底(见 3.4):GCC/Clang → attribute;IAR → __weak;其余 → UI_NO_WEAK */
#if defined(__GNUC__) || defined(__clang__)

#elif defined(__ICCARM__)
#define UI_WEAK __weak
#else

```

生成代码风格约定:
- 每屏一个编译单元,对外只暴露 `ui_screen_xxx_create/destroy`;树构建拆成 `static lv_obj_t * create_<node_name>(lv_obj_t * parent)` 静态函数(每个命名节点一个,匿名子树内联),函数体顺序固定:create → 本地属性 → 内联样式 → 命名样式 add_style → 绑定 → 事件 → 子节点。顺序固定是 golden 快照稳定的前提。
- `styles.c` 中 `ui_styles_init()` 用 `static bool inited` 防重入;样式对象 `static lv_style_t style_s_accent;` 永不释放(与 `lv_xml_style.c:295` 注释的假设一致:样式创建一次不回收)。
- 常量:`IRConst` 输出为 `#define UI_CONST_<NAME> ...`(styles.c/screens 共用)。
- **ESP-IDF 接入约定**:app 侧 `lv_init()` + 显示/触摸驱动就绪后调 `ui_init()`;主循环照常 `lv_timer_handler()`。生成器不产出 `ui_tick`——LVGL 9 的 subject/observer 是即时推送,无需轮询;留空钩子只会诱导用户往里塞逻辑。README.md 里给 3 行接入示例。

### 3.4 事件回调桩:用户代码保护 —— **决定:分文件 + weak 兜底,不用标记区**

- `actions.h`:每次重生成,列出 IR 中全部 `callback` 动作的声明:`void on_mute_clicked(lv_event_t * e);`
- `actions_default.c`:每次重生成,每个回调给 `UI_WEAK` 空实现。`UI_WEAK` 在 ui_conf.h 定义:GCC/Clang(含 Xtensa/riscv、Keil AC6)→ `__attribute__((weak))`;IAR(`__ICCARM__`)→ `__weak`;其他编译器无 weak → 定义 `UI_NO_WEAK`,actions_default.c 整文件被 `#ifndef UI_NO_WEAK` 裹空,用户必须在 actions.c 实现全部回调(INTEGRATION.md 有说明);
- `actions.c`:**只在不存在时生成**(write-if-absent),内容是把声明抄成带 TODO 注释的空函数;用户在此实现,强符号自动覆盖 weak。

理由(对比标记区方案):① 标记区要求生成器"读旧文件→解析标记→回写",任一环节出错就吞用户代码,分文件生成器是纯写入,**结构上不可能丢代码**;② 用户改名/删控件后,标记区对齐语义模糊(区块跟谁走?),分文件下旧实现最多变成 dead code,编译器给 unused warning,不阻塞;③ weak 兜底保证"刚加了事件还没写实现"时工程仍可链接运行(空转),演示/迭代体验好;④ `src/ui/` 里除 `actions.c` 外全部可宣告为"disposable,重生成即覆盖",心智模型极简,SquareLine 的 `ui_events.c` 分文件模式已被 ESP32 社区长期验证。

### 4.1 Emitter 抽象(`src/codegen/emitters/emitter.ts`)

```ts
export interface GeneratedFile { path: string; content: string }
```

### 4.2 描述表的 per-version 字段

### 4.3 降级策略框架

```ts
export type LoweringRule =
  | { action: 'drop'; warn: string }                       // 无对应物:scale → 丢弃+警告
  | { action: 'replace'; with: (node: IRNode) => IRNode }  // 结构替换:scale → meter 近似
  | { action: 'polyfill'; runtimeFile: string };           // 注入运行时:subjects → ui84_observer.c 迷你实现
export interface VersionLowering {
  widgets: Record<string, LoweringRule>;    // 9.x 独有 widget

}
```

预置基调(实现留二期):`subjects/bindings → polyfill`(观察者模式几十行可自带);`scale → replace(meter)`;`lv_obj_set_name → drop`(C 通道本来靠 objects 结构体访问,不依赖 name)。C84Emitter 在 emit 前先跑一个 `lowerForVersion(ir, rules): IRProject` 纯函数——降级发生在 IR→IR,主干 emitter 依旧无版本分支。

## 5. 正确性保障

### 5.1 Golden-file 测试

```
src/codegen/__tests__/golden/
├── cases/<case_name>/project.json        # 输入
├── cases/<case_name>/expected/xml/*.xml  # 期望输出(JSON→XML)
└── cases/<case_name>/expected/c/**/*.c|h # 期望输出(JSON→C)
```

Vitest 逐 case:`normalizeProject → emitXml/emitC94 → 逐文件字符串全等比对`;`UPDATE_GOLDEN=1` 环境变量重录。用例最小正交集:每 widget 一例、样式提升阈值边界例、绑定全 kind 一例、事件全 action 一例、圆屏 466x466 一例、重名冲突改名一例。emitter 输出确定性(排序、缩进、字段顺序)是这里的硬前提,§3.3 的固定顺序约定即为此。

### 5.2 生成 C 真编译(CI)

host gcc 直接可行,不需要 ESP-IDF:LVGL 自带 CMake 且 tests 目录本身就是 host 编译的先例。CI job:

```
codegen-compile:
  1. node scripts/gen-all-golden.mjs        # 全部 golden case 生成到 build/gen/<case>/src/ui
  2. cc -c $(find src/ui -name '*.c') \
        -I vendor/lvgl -DLV_CONF_PATH=ci/lv_conf_ci.h -DLV_LVGL_H_INCLUDE_SIMPLE \
        -Werror -Wall -Wextra
  3. 链接冒烟:ci/main_stub.c(lv_init + 内存 display + ui_init + 跑 200 次 lv_timer_handler)
     + liblvgl.a(cmake 一次性构建缓存)→ 可执行 → 运行退出码 0
```

`lv_conf_ci.h` 开 `LV_USE_XML`、`LV_USE_OBJ_NAME`、`LV_USE_TEST`,与 WASM 画布用同一份基线配置,防"CI 能编译、画布行为不同"。ESP-IDF 构建放 nightly(非阻塞):`espressif/idf` 容器 + 最小工程模板,验证 `CMakeLists.txt` 组件契约。

### 5.3 XML↔C 一致性抽查(WASM 截图比对)

两通道跑在**同一份 LVGL 9.4 源、同一渲染器(sw render)、同一 lv_conf、同一默认字体**上,理论上可像素级一致。方案:

1. 设计器 WASM 包额外导出两个入口:`designer_load_xml(name, xml)`(走 `lv_xml_register_component_from_data` + `lv_xml_create_screen`)和一个 **C golden 直链入口**——CI 把 golden case 生成的 `src/ui/*.c` 用 emcc 和画布同配置编进一个专用测试 WASM(`ui_init()` 直调);
2. 两侧各渲染一帧后取 canvas 帧缓冲(或直接在 C 侧对 draw buffer 做 CRC32,免 PNG 编解码),比对哈希;不等时才落 PNG 做像素 diff 报告;
3. 抽查矩阵 = golden case 全集,Playwright 驱动,产物挂 CI artifact。
4. 交互语义等价(点按钮 subject 变化、屏幕跳转)可后续接 `lv_xml_test` 模块(`vendor/lvgl/src/others/xml/lv_xml_test.h`,自带 `CLICK_AT/SUBJECT_COMPARE/SCREENSHOT_COMPARE` 步骤类型)驱动 XML 侧,C 侧用同脚本经 `lv_test_mouse_click_at`(tests 里现成用法,见 `test_xml_event.c`)对拍 subject 终值。

已知不可等价点登记为白名单而非糊弄:XML 侧 subject 的 `min/max` 夹取由 parser 实现,C 侧需生成 clamp observer(§3.5 已含);`lv_obj_set_name` 缺省自动命名(`lv_xml_component.c:106-117` 的 `%s_#` 规则)只存在于 XML 通道,不参与比对。

### 关键取舍一页总结

| 决策 | 选择 | 一句话理由 |
|---|---|---|
| IR 形态 | 完全解析、无版本、无引用的 lowered 树 | 两 emitter 退化为直译,等价性靠结构保证 |
| 样式策略 | 复用≥2 提升命名,否则内联 | C 侧 RAM/可维护性与文件噪音的平衡点 |
| `styles="x"` 内联挂样式 | 禁用,只用 `<style>` 子元素 | 9.4 源码中找不到该属性的应用点(仅例子残留) |
| 控件白名单 | 只做有 XML parser 的 23+obj | 画布即真值,不做不可预览的控件 |
| 用户代码保护 | 分文件 + weak 兜底 | 纯写入不可能吞代码;ESP-IDF=GCC,weak 稳 |
| 对象访问 | 每屏全局单例结构体 | 嵌入式单实例习惯,对齐 SquareLine 迁移心智 |
| 一致性验证 | 同源 LVGL 双通道帧缓冲哈希比对 | 同源同渲染器可像素级,哈希廉价、diff 兜底 |
