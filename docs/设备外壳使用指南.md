# 设备显示与外壳预览指南

本文说明如何在 LVGL Designer 中选择显示规格、使用设备外壳预览、设计圆屏界面，以及为设备构建或 `ui.podsc.com` 发布选择正确的目标。

先记住四条原则：

1. **显示预设决定真实 UI 坐标系。** 分辨率和形状会进入工程，并影响全部 Screen。
2. **画布外壳只是编辑器预览。** 它不会变成 LVGL 控件，也不会绘入 framebuffer。
3. **Controller Profile 是设备构建元数据。** 它与画布是否显示外壳是两件事。
4. **切换显示规格不会自动重排界面。** 不同产品规格通常应使用独立工程。

需要用自然语言生成或修改界面时，请同时参阅 [AI 画 UI 使用指南](AI画UI使用指南.md)。

## 1. 最短使用流程

1. 在顶部的“屏幕分辨率预设”下拉框选择目标型号。
2. 点击画布右上角的“适应窗口”，让当前 framebuffer 或整机外壳完整进入视区。
3. 隐藏外壳，按真实像素边界完成布局。
4. 显示外壳，检查开口遮挡和整机视觉效果；再次点击“适应窗口”。
5. 对圆屏检查圆周安全区，对矩形屏检查四边留白。
6. 进入运行模式，验证点击、滑动、切屏和数据绑定。
7. 设备 C 构建前选择 Controller/BuildTarget 并确认颜色格式；网站发布时选择与当前 Display 兼容的目标 frame。

> 外壳显示状态、缩放和平移都是临时视图状态，不写入工程，也不影响导出结果。

## 2. 四个容易混淆的概念

| 概念 | 解决的问题 | 是否进入工程/构建 | 是否改变画布 |
| --- | --- | --- | --- |
| 显示预设 | UI 使用多大的逻辑屏幕、是圆形还是矩形 | 是，形成 Display Profile | 是 |
| 设备外壳预览 | UI 放入产品外观后看起来怎样 | 否，仅编辑器陈列 | 否 |
| Controller Profile | 哪个控制器承载该显示、外壳视口和物理输入是什么 | 是，供设备 BuildTarget 校验 | 不直接改变 |
| 发布目标 frame | `ui.podsc.com` 上使用哪个设备型号展示 Demo | 进入网站发布记录 | 不直接改变 |

### 2.1 显示预设与 Display Profile

顶部第一个长下拉框选择显示预设。它会修改项目级 Display，具体决定：

- 逻辑宽度和高度；
- 圆形或矩形；
- LVGL framebuffer 尺寸；
- 控件可用的坐标范围；
- 圆屏预览遮罩；
- 是否能匹配内置外壳。

一个工程内的所有 Screen 共用同一 Display。把工程从 `1080×720` 矩形屏切换为 `240×240` 圆屏后，`main`、`settings` 等所有页面都会使用新的坐标系。

切换显示预设会进入撤销历史，但它只修改显示规格，不会按比例缩放或重新排列已有控件。需要同时维护圆屏、方屏或不同比例的产品时，建议分别建立工程。

### 2.2 设备外壳预览

设备外壳是随 Designer 打包的 SVG 陈列层，负责展示产品轮廓和屏幕开口。下列内容都不是 UI 的一部分：

- SVG 产品外壳；
- 编辑器灰色工作区；
- 选择框、缩放手柄和对齐参考线；
- 画布视图工具。

外壳按显示的**宽度、高度和形状**精确匹配。只有内置了对应 SVG 和开口参数时才能显示；仅在远端设备清单中增加型号，不会自动生成新的外壳素材。

### 2.3 Controller Profile

顶部第二个下拉框选择设备构建所需的 Controller Profile。Controller 可以描述：

- 所引用的 Display Profile revision；
- 产品外壳资源及屏幕在外壳中的 viewport；
- 可选的 Input Profile；
- 构建目标需要锁定的设备能力。

当前工具栏内置的是：

- `Controller 待选择`：尚未形成可发布的设备 BuildTarget；
- `裸屏（无外壳）`：使用 screen-only Controller；
- `平台目标：…`：从 Profile/BuildTarget 目录应用的正式平台目标。

选择“裸屏（无外壳）”**不会**自动隐藏画布上的 SVG 外壳。前者是构建元数据，后者是编辑器视图开关，两者互不控制。

### 2.4 `ui.podsc.com` 发布目标 frame

网站发布窗口会从目标仓库的 `site/frames/manifest.json` 读取设备清单，并按当前 Display 的形状、分辨率或宽高比判断兼容性。它与设备 C 构建使用的 Controller/BuildTarget 是不同链路：

- 设备构建关注 Controller、Display、颜色格式和能力引用；
- 网站发布关注目标 frame 与当前 UI 坐标系是否兼容。

## 4. 选择和切换显示规格

### 4.1 选择正式预设

1. 打开顶部“屏幕分辨率预设”。
2. 选择目标型号。
3. 等待 LVGL 9.5 WASM 预览重新加载。
4. 点击“适应窗口”。
5. 核对型号、逻辑宽高和形状。
6. 逐屏检查已有控件是否越界或被裁切。

下拉框中可能出现两类不可选项：

- `分辨率待登记`：设备清单只有型号/形状，没有可采用的分辨率或 Demo 尺寸；
- `当前：…（自定义工程，仅兼容）`：导入的工程使用自定义规格，当前没有对应的一键预设。

### 4.2 圆屏与矩形屏互切

选择 `WF2D-8620` 后，项目会切换到 `240×240` 圆形 Display。画布坐标仍是 `0..239 × 0..239` 的方形 framebuffer，但四角不属于物理可视圆。

从圆屏切回矩形预设后，应重点检查：

- 固定坐标是否仍合理；
- 横向或纵向留白是否失衡；
- 全屏背景、列表和弹窗是否填满新画布；
- 触控目标是否仍位于预期位置。

只把按钮做成圆角或在矩形画布中绘制圆形背景，并不等于真实圆屏设计。

### 4.3 不要把物理尺寸当成像素尺寸

`86×86 mm` 描述产品外形，`240×240 px` 描述 framebuffer。两者作用不同，不能互相替代。控件布局始终使用逻辑像素；物理尺寸主要用于产品说明和目标设备识别。

## 5. 显示、隐藏和缩放外壳

画布右上角最后一个按钮控制设备外壳：

- 高亮：显示匹配的设备外壳；
- 未高亮：只显示 framebuffer；
- 禁用：当前宽度、高度、形状没有匹配的内置外壳。

隐藏外壳不会改变 Display，也不会把圆屏改成矩形屏。切换外壳后建议再次点击“适应窗口”，因为：

- 显示外壳时，“适应窗口”会容纳整机轮廓；
- 隐藏外壳时，“适应窗口”只需容纳 framebuffer。

推荐使用下面的双视图检查法：

1. **无外壳视图**：检查像素边界、控件尺寸、对齐和可点击区域；
2. **有外壳视图**：检查产品观感、开口遮挡和视觉重心。

### 5.1 画布视图操作

| 操作 | 效果 |
| --- | --- |
| `Ctrl/Cmd + 滚轮` | 以鼠标位置为中心缩放，范围 25%–800% |
| 普通滚轮 | 垂直平移 |
| `Shift + 滚轮` | 水平平移 |
| 按住空格拖动 | 自由平移 |
| `Shift + 1` | 适应窗口 |
| “重置视图”按钮 | 恢复 100% 并居中 |
| 方向键 | 移动选中控件 1 px |
| `Shift + 方向键` | 移动选中控件 10 px |
| `Ctrl/Cmd + 方向键` | 调整选中控件宽高 1 px |
| `Ctrl/Cmd + Shift + 方向键` | 调整选中控件宽高 10 px |

切换活动 Screen 或改变显示宽高时，视图会回到 100% 并居中。这只重置观察视角，不修改控件坐标。

## 6. 圆屏布局与安全区

### 6.1 圆屏裁切模型

以 `240×240` 圆屏为例：

- 圆心是 `(120, 120)`；
- 可视圆半径是 `120 px`；
- framebuffer 仍为 240×240；
- 四角像素存在于缓冲区，但不在物理可视圆内；
- 显示外壳时由圆形开口表现可视范围；
- 隐藏外壳时由 Overlay 绘制圆形遮罩和边界。

### 6.2 可执行的安全区规则

重要文字和主要触控控件建议距离圆周至少 `12–18 px`。判断一个控件是否安全时，应检查它四个角，而不是只检查中心点。

对 `240×240` 圆屏，采用 `18 px` 安全边距时，可按以下公式检查控件每个角 `(x, y)`：

```text
(x - 120)² + (y - 120)² ≤ 102²
```

若希望用更简单、保守的矩形区域，可把关键信息放在约 `x=48..192、y=48..192` 内。标题、弧形刻度等贴近圆周的内容可以超出该矩形，但仍应逐角检查。

设计建议：

- 核心数值和主操作放在中心区域；
- 顶部标题避免贴近圆周最高点；
- 底部按钮优先使用短文字和适中的宽度；
- 长文本应换行、精简或改用图标；
- 列表减少列数，并避免在四角放置重要信息；
- 在设计模式和运行模式各检查一次。

### 6.3 圆屏内容被裁切时

按以下顺序排查：

1. 点击“适应窗口”，排除观察视图的问题；
2. 隐藏外壳，直接查看 framebuffer 和圆形遮罩；
3. 选中控件，检查整个边界框而非控件中心；
4. 缩小控件或向圆心移动；
5. 缩短文字，避免文本实际宽度超过控件预估；
6. 进入运行模式再次验证。

## 7. 设备构建与网站发布

### 7.1 设备 C 构建前

设备构建需要形成一致的不可变引用链：

```text
UiProject.designDisplayRef
          │
          ├── 必须等于 ControllerProfile.displayRef
          │
          └── BuildTarget 锁定 Controller / Display / Theme revision
```

构建前确认：

- Display Profile 的逻辑宽高和形状正确；
- 已选择正式 Controller，或明确使用“裸屏（无外壳）”；
- 16bpp 项目已确认 `RGB565` 或 `RGB565_SWAPPED`；
- BuildTarget 引用的 revision 与当前快照一致；
- 跨引用和目标能力校验通过。

Designer 的预览 SVG 不会编译成 LVGL 控件或 framebuffer。构建清单可以记录 Controller/Profile 引用，但这不等于把编辑器外壳绘入 UI。

### 7.2 发布到 `ui.podsc.com` 前

发布窗口会单独选择目标设备型号。确认：

- 目标 frame 与当前 Display 的形状一致；
- 已登记分辨率的型号必须与当前逻辑宽高完全一致；
- 未登记分辨率但声明了宽高比的型号必须满足比例容差；
- 发布缩略图和可交互预览中的内容完整；
- 不要把 Designer 离线快照当成目标仓库最新清单。

目标网站可以使用自己的 frame 资源包装 Demo；这与 Designer 画布里的 SVG 预览资源彼此独立。

## 8. 常见问题

### 外壳按钮为什么不可点击？

当前 Display 没有匹配的内置 SVG 外壳。请选择正式预设；如果是新型号，需要由开发人员补充设备清单、SVG 和开口参数。Designer 暂不支持在界面中上传自定义外壳。

### 为什么选择“裸屏（无外壳）”后仍能看到外壳？

“裸屏”属于 Controller Profile；画布外壳属于编辑器视图。点击画布右上角的外壳按钮即可隐藏。

### 为什么显示外壳后画布突然变小？

“适应窗口”需要把整个产品外形放进视区，屏幕开口自然会比无外壳模式小。需要精细编辑时隐藏外壳并再次适应窗口。

### 圆屏外面为什么仍有方形区域？

方形区域可能是 SVG 外边界、编辑器工作区或底层方形 framebuffer。真实可视范围以圆形开口和遮罩为准。

### 切换设备后布局为什么变乱？

Designer 不会自动进行响应式重排。固定坐标和尺寸仍保留原值，需要手动调整；长期维护的设备变体应拆成独立工程。

### `WF2D-8630` 为什么显示 480×480，却又提示分辨率待登记？

`480×480` 是当前 Demo 逻辑画布，用于编辑和网站演示；硬件分辨率尚未在权威清单中登记。不要据此生成最终固件配置。

### 发布窗口提示型号不兼容怎么办？

不要强行选择目标。先核对当前 Display 的宽、高和形状，再选择兼容 frame；如果硬件参数确实已更新，应先修正目标仓库的权威 manifest。

### 中文为什么显示成方框？

这是字体缺少中文字形，不是外壳问题。导入中文字体并在控件样式中使用，参见 [素材管线说明](asset-pipeline.md)。

## 9. 推荐验收清单

### 设计验收

- [ ] 顶部设备型号、逻辑宽高和形状正确；
- [ ] 每个 Screen 都适配同一 Display；
- [ ] 无外壳视图下控件没有越界；
- [ ] 有外壳视图下开口与 framebuffer 对齐；
- [ ] 圆屏关键信息位于安全区；
- [ ] 运行模式下点击和切屏正常；
- [ ] 字体、图片和动画资源完整。

### 设备构建验收

- [ ] Controller 与 Display 引用一致；
- [ ] BuildTarget 锁定正确 revision；
- [ ] 颜色格式已确认；
- [ ] 跨引用和能力校验通过；
- [ ] 导出的 UI 不包含编辑器陈列层。

### 网站发布验收

- [ ] 目标 frame 与当前 Display 兼容；
- [ ] 缩略图与可交互预览正确；
- [ ] 发布清单差异符合预期；
- [ ] Git、静态上传、旧页清理和 CDN 状态均已确认。

## 10. 新增设备外壳（开发人员）

新增型号不是只放入一张 SVG。完整流程是：

1. 在 `ui.podsc.com/site/frames/manifest.json` 登记型号、形状、物理尺寸和权威分辨率；硬件分辨率未确认时只能登记 Demo 逻辑尺寸或宽高比。
2. 将 SVG 加入 Designer 的设备外壳资源目录。
3. 在 `DEVICE_FRAME_PREVIEWS` 中登记 SVG、匹配宽高、形状和归一化开口参数。
4. 同步公开静态 frame 资源，供需要直接访问资源的消费者使用。
5. 补充预设解析、外壳匹配和发布兼容性测试。
6. 生产构建后分别检查矩形、圆形、有外壳和无外壳视图。

开口参数采用 SVG 外框的归一化比例，而不是屏幕像素：

```ts
aperture: { x, y, width, height, radius }
```

`x/y/width/height` 的范围通常为 `0..1`；`radius` 使用 CSS 圆角值，例如圆形开口使用 `50%`。
