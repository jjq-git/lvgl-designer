## 1. 总体目录结构

### 1.1 结论:pnpm workspace 单仓多包

理由:
- `schema`(工程 JSON 类型 + widget 描述表)必须同时被 **designer(浏览器)** 和 **codegen(纯 Node,可跑 vitest/CLI)** 消费。单包做不到"codegen 不拖 React 依赖、可独立跑单测/将来出 CLI";两仓则违背单人项目的维护成本约束。
- `codegen` 的 IR→emitter 结构(一期 xml-emitter + c94-emitter,二期加 c84-emitter)是纯函数库,放独立包能用 golden-file 快照单测,不需要起浏览器。
- WASM 运行时(Emscripten 产物 + C 桥源码)构建工具链完全不同(emcmake/cmake),放 `runtime/` 顶层目录,产物发布到 `packages/lvgl-runtime/dist/`,前端只依赖 TS 包装包,不感知 emsdk。

## 2. 状态管理选型:Zustand + Immer(否决 MobX / RTK)

场景特征:大 JSON 树(几百~几千节点)、高频属性编辑(拖动时 60Hz 写 x/y)、undo/redo、派生副作用(XML 重生成→WASM)。

| 候选 | 评估 |
|---|---|
| **Zustand + immer 中间件** ✅ | ① `produceWithPatches` 让 undo/redo 成为一等公民(§3),不需要额外抽象;② 结构共享 + selector 浅比较,属性面板只订阅 `selectSelectedNode`,拖动 x/y 时对象树/画布外组件零重渲;③ store 可在 React 之外读写——**热重载管线是 store 订阅,不是 React effect**,与渲染节拍解耦;④ 体积 ~1KB,无样板 |
| MobX ❌ | 细粒度响应快,但:① undo/redo 要靠 mobx-keystone/mst 才有 patch 流,引入整套模型层,与"工程格式 = 平面 JSON schema(zod 校验、直接序列化)"冲突;② Proxy 包裹数千节点的树有内存/调试成本;③ 序列化前要 toJS 剥壳,导入导出/worker 传递都多一层 |
| Redux Toolkit ❌ | 同样基于 immer,能力等价但样板重(slice/action/dispatch);时间旅行 devtools 对本项目价值低(我们自己就要实现历史栈);无收益 |

**双 store 切分**(关键决策):
- `projectStore`:**可持久化、可 undo** 的文档状态(即 `.lvproj.json` 的内存形态)。
- `editorStore`:**瞬态** UI 状态——选中 id、悬停 id、画布 zoom/pan、面板尺寸、拖拽会话。**绝不进历史栈、绝不进工程文件**。选中变化不产生 undo 项(与 Qt Designer 行为一致)。

## 3. Undo/Redo:immer patches + 交互合并(否决 command 模式)

### 3.1 选型理由

- Command 模式要求每种编辑操作手写 `do/undo` 双向逻辑(移动、改属性、删子树、重排…),删子树的逆操作(带完整子树+索引恢复)极易写错;immer 的 `produceWithPatches` 自动产出 `patches/inversePatches`,**任何** recipe 天然可逆,新增编辑操作零 undo 成本。
- Command 模式的传统优势(语义化合并)用 `coalesceKey` 一样能做(§3.3)。
- 代价:patch 是 JSON-Pointer 粒度,历史项占内存略大——用 `limit: 200` 环形栈封顶,可接受。

### 3.2 核心 store 接口(`apps/designer/src/stores/projectStore.ts`)

```ts
import type { Patch } from 'immer';
import type { Project } from '@lvd/schema';

export interface HistoryEntry {
  label: string;                 // "移动 slider_1" — 供 UI 显示
  patches: Patch[];
  inversePatches: Patch[];
  coalesceKey?: string;          // 相同 key 的连续条目合并为一条
  ts: number;
}

export interface MutateOptions {
  coalesceKey?: string;          // e.g. `drag:${nodeId}` / `prop:${nodeId}:width`
  /** true = 只改 state 不记历史(拖动的中间帧),配合 commitInteraction 收尾 */
  transient?: boolean;
}

export interface ProjectStore {
  project: Project;
  revision: number;              // 每次 mutate +1,热重载管线的订阅键
  dirty: boolean;                // 自动保存标记

  /** 唯一写入口。所有编辑操作(含 DnD 落点、检查器改值)都走它 */
  mutate(label: string, recipe: (draft: Project) => void, opts?: MutateOptions): void;

  /** 交互收尾:把自 beginInteraction 以来的 transient 累积 patch 压成一条历史 */
  beginInteraction(label: string, coalesceKey: string): void;
  commitInteraction(): void;     // pointerup 调
  abortInteraction(): void;      // Esc 调:回放累积的 inversePatches

  undo(): void;
  redo(): void;
  canUndo(): boolean;
  canRedo(): boolean;

  history: { undoStack: HistoryEntry[]; redoStack: HistoryEntry[]; limit: 200 };

  loadProject(p: Project): void; // 导入/新建:清空历史
}
```

实现要点:`mutate` 内 `const [next, patches, inverse] = produceWithPatches(get().project, recipe)`;写历史时若 `opts.coalesceKey === 栈顶.coalesceKey && ts 差 < 800ms`,则 `栈顶.patches.push(...patches)`、`栈顶.inversePatches.unshift(...inverse)`,不新增条目;任何新 mutate 清空 redoStack。`undo` = `applyPatches(project, entry.inversePatches)` 并移入 redoStack。

### 3.3 连续拖动 = 一条历史

拖动手柄的事件流:

```
pointerdown → beginInteraction("移动 slider_1", `drag:${id}`)
pointermove → mutate(..., draft => { node.x=…; node.y=… }, { transient: true })   // 60Hz
pointerup   → commitInteraction()   // 累积 patch 压成一条 HistoryEntry
```

属性面板里拖 number 输入的步进器同理,`coalesceKey: "prop:${id}:${propName}"` + 800ms 时间窗合并,无需 begin/commit。

### 3.4 与热重载管线的整合(`apps/designer/src/canvas/reloadPipeline.ts`)

两条通道,按代价分流:

```ts
projectStore.subscribe((s, prev) => {
  if (s.revision === prev.revision) return;
  const delta = classify(lastPatches);          // mutate 时顺手存的本次 patches

  if (delta.kind === 'attr-only') {
    // 快路径:只有属性值变(拖动 x/y、改颜色)→ lv_xml_update_from_data,不重建树
    bridge.updateFromXml(emitUpdateSnippet(delta));    // <lv_slider name="obj_x" x="30"/>
  } else {
    // 慢路径:结构变化(增删/重排/换屏)→ 防抖 80ms 全量重生成
    debouncedFullReload();  // unregisterComponent → registerComponent(新 XML) → createScreen
  }
});
```

- 快路径依据:`lv_xml_update_from_data` 按 `name` 找到既有控件、只应用属性,签名见 `vendor/lvgl/src/others/xml/lv_xml_update.h:28-34`。因此 **XML emitter 必须给每个节点输出 `name="<节点id>"`**(obj 解析器支持 name:`lv_xml_obj_parser.c:88`),这同时是命中测试 `objAtPoint` 返回值的关联键。
- 慢路径防抖 80ms(trailing),`commitInteraction`/undo/redo 后强制立即 flush 一次,保证松手即所见即最终态。
- undo/redo 本身也走同一订阅,天然驱动画布回放。

### 4.3 描述表驱动的属性检查器

**描述表是 schema 包的一部分**(检查器生成表单、codegen 校验/序列化、二期 8.4 兼容过滤,三方共用一份):

```ts
// packages/schema/src/widgets/types.ts
export type PropKind =
  | 'int' | 'size'          // size 支持 px/%/content(lv_xml_to_size 语义)
  | 'bool' | 'string'
  | 'enum'                  // options 驱动 <Select>

export interface PropSpec {
  name: string;             // 必须与 XML 属性名逐字一致(照抄 parser 源码)

};
```

样式页签同理:样式属性描述表按 `lv_xml_style.c` 的 `SET_STYLE_IF` 宏展开清单建表(`vendor/lvgl/src/others/xml/lv_xml_style.c:45` 起),行内覆盖以 `style_` 前缀属性输出(obj 解析器在 `lv_xml_obj_parser.c:166` 处理 `style_*`,选择器语法 `style_bg_color:pressed|knob` 见 `lv_xml_style.c:331` 的 `lv_xml_style_string_process`)。

### 4.4 DnD 选型:画布自研 pointer events,对象树用 dnd-kit

关键约束:**拖拽落点是 WASM canvas 上的一个 LVGL 控件,不是 DOM 节点**。dnd-kit 和 HTML5 DnD 的碰撞检测/droppable 都基于 DOM 矩形,对 canvas 内部无能为力——canvas 整体只是一个 droppable,内部命中必须问 LVGL(`bridge.objAtPoint`)。硬套 dnd-kit 等于只用它的 ghost 渲染,却要绕过它整个碰撞层,得不偿失。

方案:
- **组件面板 → 画布、画布内移动/缩放**:自研 `PointerDnd`(`apps/designer/src/canvas/dnd/PointerDnd.ts`),约 200 行:
  1. palette item `onPointerDown` → `setPointerCapture` → 克隆 ghost 元素跟随光标;
  2. move 到 canvas 上方时换算画布坐标 `(clientXY - canvasRect) / zoom` → `bridge.objAtPoint(x,y)` 得候选父节点 id → 沿工程树上溯到最近 `isContainer` 节点 → `bridge.getObjRect(id)` 画蓝色落点高亮框(Overlay 层);
  3. `pointerup` → `projectStore.mutate('添加 slider', draft => insertChild(...))` → 慢路径热重载;
  4. HTML5 DnD 被否决的另一原因:无法自定义拖动中的实时命中反馈节流,且移动端/触屏行为不一致。
- **对象树内重排**:纯 DOM 列表排序,`@dnd-kit/sortable` 是成熟解,直接用;drop 结果同样落到 `projectStore.mutate`。树 → 画布(把树节点拖进另一个容器)统一走 PointerDnd,树节点也注册为拖拽源。

### 4.5 Overlay(选择框/手柄/圆屏遮罩)

- `Overlay.tsx` 绝对定位覆盖 canvas,`pointer-events: none`,仅手柄元素 `pointer-events: auto`。
- 选中框坐标 = `bridge.getObjRect(selectedId)` × zoom;订阅 `projectStore.revision` 和 `editorStore.selectedId` 在 rAF 中刷新(热重载后 rect 可能变)。
- 8 手柄拖拽 → §3.3 事件流,写回 `x/y/width/height`(均为 obj 基类 XML 属性,`lv_xml_obj_parser.c:92-95`)。
- **圆屏遮罩**:`display.shape === 'round'` 时叠一层 `div`,`background: 遮罩色; -webkit-mask/mask: radial-gradient` 或直接 `clip-path: circle(50%)` 的反向蒙版,加 1px 圆周描边;纯 CSS,零 WASM 改动,GC9A01(240×240)/ST7102(466×466) 预设进"显示器"下拉。

## 5. 素材管线

### 5.1 字体:预览走 tiny_ttf(零转换),导出走 lv_font_conv(worker)

**核心事实(本仓核实)**:9.4 的 XML `<fonts>` 原生支持两种源——`<tiny_ttf src_path="..." size="32">`(运行时 `lv_tiny_ttf_create_file`,`vendor/lvgl/src/others/xml/lv_xml_component.c:390-406`)和 `<bin src_path="...">`(`lv_binfont_create`,同文件 :425)。测试样例 `vendor/lvgl/tests/src/test_assets/xml/globals.xml` 两者都有。

据此把"预览"和"导出"解耦:

- **预览路径(M2 即用,无风险)**:用户上传 TTF → `bridge.writeAsset('/assets/fonts/xx.ttf', bytes)` 写 MEMFS → globals XML 里生成 `<tiny_ttf name="..." src_path="fonts/xx.ttf" size="N" as_file="true"/>`(配合 `lv_xml_set_default_asset_path("A:/assets/")`,`lv_xml.h:84`)。**浏览器里根本不用跑 lv_font_conv**。WASM 构建需 `LV_USE_TINY_TTF=1`(源码在 `vendor/lvgl/src/libs/tiny_ttf/`)。与 lv_font_conv 位图字体的渲染有亚像素级差异,可接受。
- **导出路径(生成 C 数组字体)**:在 Web Worker 跑 `lv_font_conv` 的库入口。已知事实与待验证项:
  - lv_font_conv 是 npm 包、纯 JS、除 CLI 外提供库入口(README 宣称 "Can be used as a library"),入口约为 `lv_font_conv/lib/convert.js`,签名约为 `convert({ font: [{ source_bin: Buffer, ranges }], size, bpp, format: 'lvgl'|'bin', lv_include, no_compress })` →【待验证:装包后读 node_modules 确认入口路径与参数名】。
  - 依赖面(印象中为 argparse/bit-buffer/opentype.js/pngjs 一类,均无原生模块)→【待验证:读其 package.json】。风险点是 Node `Buffer`/`fs` 引用:用 `vite-plugin-node-polyfills` 注入 Buffer/process,`source_bin` 直接传内存 Buffer 避开 fs。
  - **兜底**(若库入口在浏览器跑不通):导出物改为 `format: 'bin'` 同样跑不通时,提供"下载字体转换任务描述 + 本地一条 npx 命令"的降级导出;预览不受影响。
  - worker 协议(`apps/designer/src/services/workers/fontConv.worker.ts`):`postMessage({ ttf: ArrayBuffer, size, bpp: 1|2|4, ranges: string }) → { cFile: string, binFont: Uint8Array }`,transferable 传递。
- 产出的 `.bin` 字体同时回灌预览(globals XML 用 `<bin>`),让"导出前预览位图字体真实效果"成为可选开关。

### 5.2 图片:预览走 PNG 解码,导出走自写 v9 编码器

- **预览**:WASM 开 `LV_USE_LODEPNG=1`(`vendor/lvgl/src/libs/lodepng/` 在源码树内)→ 用户上传 PNG/JPG(JPG 先经 OffscreenCanvas 转 PNG)写 MEMFS → globals XML `<images><file name="logo" src_path="images/logo.png"/></images>`(语法见 tests globals.xml)。
- **导出**:`packages/asset-pipeline/src/image/encodeV9.ts` 自写编码器,不依赖 lv_img_conv(v9 的 `lv_image_dsc_t` = header{magic/cf/flags/w/h/stride} + data,格式一期支持 RGB565、RGB565A8、ARGB8888、I8;实现时对照 `vendor/lvgl/src/draw/lv_image_dsc.h` 逐字段写)。解码在 worker:`createImageBitmap` + `OffscreenCanvas.getContext('2d').getImageData()` 拿 RGBA,再按目标 cf 打包 + 生成 C 数组文本。
- worker 协议:`{ png: ArrayBuffer, cf: 'RGB565'|'RGB565A8'|'ARGB8888'|'I8', dither?: boolean } → { cFile: string, preview: ImageBitmap }`。

### 5.3 存储:IndexedDB 分离存储(内部)+ base64 内嵌(仅导出文件)

结论:**两者都要,分场景**。
- 内部工作副本:素材字节存 IndexedDB `assets` 表(content-addressed,key = sha-256 hash),工程 JSON 只存 `AssetRef{ id, hash, name, meta }`。理由:自动保存每 2s 序列化一次工程 JSON,若内嵌 base64,一张 466×466 PNG 会让每次自动保存膨胀数百 KB 且 JSON.stringify 反复拷贝大字符串;分离后素材写一次、引用不变零成本。
- `.lvproj.json` 导出:为满足"单文件下载/上传即可迁移",导出时把引用的素材以 base64 内嵌到 `assets[i].data` 字段;导入时拆出写回 IndexedDB。文件体积换可移植性,值得。

## 6. 持久化

### 6.1 IndexedDB 结构(用 `idb` 库,`apps/designer/src/services/storage/`)

```
DB: lvgl-designer (version 1)
├── projects   key=projectId  → { meta:{name, updatedAt, thumbnailPng}, doc: Project }  // 最新态
├── snapshots  key=auto       → { projectId, ts, doc }        // 自动保存环形备份,每项目留 10 份
└── assets     key=sha256hex  → Blob                          // 内容寻址,跨项目去重
```

自动保存策略:`projectStore` 订阅 `dirty` → debounce 2s 写 `projects`;每 2 分钟或结构性大改(删屏/删子树)后追加一条 `snapshots`;`visibilitychange(hidden)` 与 `beforeunload` 时同步 flush。崩溃恢复:启动时发现 `projects.updatedAt > 上次正常关闭标记` 则提示恢复。

### 6.2 StorageProvider 接口(Gitea 接缝)

```ts
// apps/designer/src/services/storage/provider.ts
export interface ProjectMeta { id: string; name: string; updatedAt: number; origin: 'local' | 'gitea' }

export interface StorageProvider {
  readonly id: 'indexeddb' | 'gitea';
  list(): Promise<ProjectMeta[]>;
  load(id: string): Promise<{ doc: Project; assets: Map<string, Blob> }>;
  save(id: string, doc: Project, assets: Map<string, Blob>): Promise<void>;
  remove(id: string): Promise<void>;
}
```

一期只实现 `IndexedDbProvider`;`GiteaProvider` 二期用 contents API(`PUT /api/v1/repos/{owner}/{repo}/contents/{path}`,base64 body)实现同一接口——素材以仓库内独立文件存放而非 base64 内嵌,`save` 做多文件批量提交。"最近项目列表"读 `list()` 聚合各 provider,UI 无需改动。

### 6.3 导入导出与迁移

- 导出:`serializeProject(doc, assets): string`(schema 包)→ 触发下载 `<name>.lvproj.json`。
- 导入:`JSON.parse` → `projectZod.safeParse` → 失败给出字段级错误;`formatVersion < CURRENT` 时依次跑 `migrations.ts` 注册的 `(doc: unknown) => unknown` 链。**从第 1 版就带 `formatVersion` 和迁移注册表**,这是 8.4 二期与后续 schema 演进的保险。

## 关键取舍一览

| 决策 | 选择 | 一句话理由 |
|---|---|---|
| 仓库形态 | pnpm workspace 4 包 + runtime/ | schema/codegen 需脱离浏览器复用与单测;WASM 工具链隔离 |
| 状态 | Zustand + immer 双 store | patches 即 undo/redo;文档态与瞬态分离;订阅驱动热重载不过 React |
| Undo | immer patches + coalesceKey | 自动可逆,拖动 60Hz 合并为一条历史 |
| 热重载 | 属性改动走 `lv_xml_update_from_data` 快路径,结构改动防抖全量 register/create_screen | 拖动零重建;API 均在 9.4 源码核实 |
| DnD | 画布自研 pointer events,树用 dnd-kit | 落点在 canvas 内部,命中必须问 LVGL,DOM 型 DnD 库帮不上 |
| 字体预览 | tiny_ttf 直读 TTF(MEMFS),lv_font_conv 只在导出期 worker 跑 | 消掉浏览器跑 npm 字体转换器这个最大不确定性(其库入口浏览器兼容性【待验证】) |
| 素材存储 | IndexedDB 内容寻址 + 导出时 base64 内嵌 | 自动保存不背 base64 膨胀,单文件可移植不丢 |
| 前端先行 | LvglBridge 接口 + mockBridge | 无 WASM 也能开发全部面板逻辑 |

**待验证清单(M0/M1 期间消化)**:① `lv_font_conv/lib/convert.js` 入口路径、参数名、浏览器可运行性(装包后读 node_modules);② 其依赖是否含 fs/Buffer 硬引用及 polyfill 可行性;③ `lv_xml_update_from_data` 对嵌套组件内 name 的作用域行为(读 `lv_xml_update.c` + M0 实测);④ SINGLE_FILE 产物体积与 32MB 初始堆在 466×466 双缓冲下是否够用。
